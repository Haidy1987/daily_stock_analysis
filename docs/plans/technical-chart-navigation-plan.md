# 技术图表页面导航入口规划

## 1. 规划目的

为“技术指标图表第一版”增加一个可直接访问的一级页面入口，让用户不必先进入首页、选择股票或打开历史趋势抽屉，便可以独立查看 K 线、均线、成交量、MACD、RSI 和支撑压力。

本规划只定义导航、路由、页面入口和联动边界；图表数据接口和指标范围以[技术指标图表第一版需求文档](technical-chart-v1-requirements.md)为准。

## 2. 推荐方案

| 项目 | 建议 |
| --- | --- |
| 菜单名称 | 技术图表 |
| 英文名称 | Technical Chart |
| 路由 | `/technical-chart` |
| 图标 | 优先使用 `CandlestickChart`；当前 lucide 版本不可用时使用 `ChartNoAxesCombined` 或 `LineChart` |
| 菜单层级 | 一级导航 |
| 推荐位置 | “选股”之后、“持仓”之前 |
| 访问方式 | 侧边栏点击、首页股票上下文跳转、URL 查询参数直达 |
| 权限 | 不新增页面级角色限制，沿用系统全局认证策略 |

选择一级菜单的原因：技术图表是一个独立的高频分析工作台，不应依附于某一次分析报告；同时它与“选股”属于行情研究入口，放在相邻位置更容易形成使用路径。

## 3. 导航结构调整

### 3.1 PC / Mac 侧边栏

建议调整为：

1. 首页
2. 问股
3. 选股（AlphaSift 开启时显示）
4. 技术图表
5. 持仓
6. AI 建议
7. 回测
8. 告警
9. 用量
10. 账户
11. 用户管理（管理员可见）
12. 设置

技术图表不应设置 `adminOnly` 或依赖 AlphaSift 开关。只要应用可以访问行情数据，就应显示该入口；如果后端开启了全局登录，访问行为仍由现有认证守卫统一处理。

### 3.2 移动端导航

移动端沿用现有侧边栏抽屉或折叠导航，不额外创建一套移动端菜单。需要保证：

- “技术图表”在折叠菜单中有明确图标和可访问名称。
- 点击后自动关闭导航抽屉，并进入 `/technical-chart`。
- 当前路由激活样式与 PC 端一致。
- 菜单项较多时不把技术图表隐藏到不可发现的二级区域；若未来需要分组，归入“市场分析”分组。

## 4. 路由与页面入口

### 4.1 路由定义

在现有 Web 路由中新增：

```text
/technical-chart
```

页面应使用懒加载，避免用户只访问首页时立即加载图表库和技术指标组件。

建议支持以下查询参数：

| 参数 | 示例 | 说明 |
| --- | --- | --- |
| `stock` | `600519` | 股票代码或标准化股票标识 |
| `period` | `daily` | 第一阶段仅 `daily`；周线/月线待后端完成聚合后启用 |
| `days` | `120` | 历史数据点数量 |
| `indicators` | `ma,volume,macd,rsi` | 初始启用的指标集合 |

示例：

```text
/technical-chart?stock=600519&period=daily&days=120
```

查询参数只作为页面初始状态，不应绕过后端参数校验。用户在页面内切换股票、周期或时间范围后，可以同步更新 URL，便于刷新、复制和浏览器前进/后退。

### 4.2 页面状态

页面至少需要覆盖以下状态：

1. 无股票：显示股票搜索框、最近查看股票或自选股快捷入口。
2. 正在加载：显示图表骨架屏或 loading 状态。
3. 加载成功：显示完整技术图表和当前股票上下文。
4. 数据不足：保留可用 K 线，指标不足部分显示空值提示。
5. 无行情数据：说明当前股票或周期暂无数据。
6. 接口失败：显示错误信息和重试按钮，不让页面整体白屏。
7. 股票代码非法：在输入区域提示格式或查询失败原因。

## 5. 页面布局规划

### 5.1 顶部股票上下文

页面顶部建议包含：

- 股票代码 / 股票名称搜索框。
- 当前市场标识（A 股、港股、美股等，具体以现有股票标准化逻辑为准）。
- 当前周期和数据范围。
- 刷新按钮以及最近数据日期。
- “回到首页分析”快捷操作。

如果用户从首页股票卡片或历史记录进入，应将当前股票自动带入页面；不要要求用户再次输入。

### 5.2 图表主体

图表主体复用第一版技术图表需求中的多面板结构：

- 主图：K 线、MA5/MA10/MA20、支撑压力。
- 副图一：成交量。
- 副图二：MACD。
- 副图三：RSI。

技术图表页面应成为图表组件的主要承载页。现有历史趋势抽屉后续可以复用同一组件，但不应复制一套指标计算或图表渲染实现。

### 5.3 右侧或顶部快捷操作

第一版建议提供：

- 指标显示开关。
- 时间范围切换。
- 周期切换。
- 恢复默认视图。

“保存为我的指标模板”不纳入第一版，避免导航入口上线时同时引入用户偏好数据结构和多用户隔离问题。

## 6. 与现有页面的联动

### 6.1 首页

在首页以下位置可增加跳转按钮，但作为第二步联动实现：

- 股票分析结果卡片：`查看技术图表`。
- 历史分析记录的股票操作菜单：`打开技术图表`。
- 股票搜索结果：`技术图表`快捷动作。

跳转统一使用：

```text
/technical-chart?stock={normalizedStockCode}
```

### 6.2 选股页

选股结果行可以增加“查看图表”操作。该操作只传递股票上下文，不把选股策略结果硬编码进技术图表页面；后续如需显示选股信号，应另行定义数据契约。

### 6.3 持仓页

持仓列表可以增加单行跳转入口，但第一版不将持仓成本、盈亏或交易数据注入公共技术图表 API。若未来需要显示用户持仓线，应在用户授权和数据隔离方案明确后单独设计。

### 6.4 历史趋势抽屉

现有历史趋势抽屉可以保留轻量趋势图。第一版技术图表页面上线后，再评估是否将抽屉中的“历史趋势”替换为技术图表摘要，避免一次打开抽屉加载大量指标数据。

## 7. 权限与多用户边界

- 技术图表查询的是公共行情和技术指标，不按用户复制数据。
- 页面入口不设置管理员限制，也不依赖用户是否拥有自选股。
- 当系统认证开启时，页面仍遵循现有全局登录守卫。
- 未登录用户能否访问公共图表，取决于项目整体认证模式，不在导航改造中新增例外。
- 如果用户从自选股、持仓或历史数据进入，只传递股票代码；自选股和持仓详情仍必须由现有用户隔离接口控制。
- 后续保存图表偏好时，必须绑定当前用户，并禁止把偏好写成全局配置。

## 8. 国际化与可访问性

需要补齐中英文 UI 文案，至少包括：

- `layout.nav.technicalChart`
- `technicalChart.pageTitle`
- `technicalChart.pageDescription`
- `technicalChart.searchStock`
- `technicalChart.emptyTitle`
- `technicalChart.emptyDescription`
- `technicalChart.openFromHome`

菜单项和图标必须同时具备可读文本与 `aria-label`。折叠导航只显示图标时，仍要通过 tooltip 或 `aria-label` 告知“技术图表”。

## 9. 实施拆分

### 阶段一：入口骨架

1. 新增 `TechnicalChartPage` 懒加载页面。
2. 在 `App.tsx` 注册 `/technical-chart` 路由。
3. 在 `SidebarNav.tsx` 增加一级导航项。
4. 增加中英文导航文案、页面标题和空状态。
5. 页面在无股票参数时可正常打开。

### 阶段二：股票上下文

1. 接入现有股票搜索、最近股票或自选股候选能力。
2. 解析并校验 `stock`、`period`、`days` 查询参数。
3. 在页面内切换股票和范围时同步 URL。
4. 增加首页、选股页和持仓页的快捷跳转。

### 阶段三：图表接入

1. 接入技术图表 API。
2. 复用统一技术图表组件，渲染 K 线、MA、成交量、MACD、RSI 和支撑压力。
3. 增加 loading、空数据、错误、重试和数据不足状态。
4. 验证 PC、Mac、移动端和桌面端内嵌页面。

### 阶段四：体验收敛

1. 优化图表库懒加载和页面首屏性能。
2. 检查深色/浅色主题、窄屏布局和折叠菜单。
3. 补充路由、菜单、查询参数和页面状态测试。
4. 提供页面截图作为 UI 变更验收证据。

## 10. 测试与验收标准

### 导航与路由

- 未开启 AlphaSift 时，技术图表仍显示在侧边栏。
- 普通用户和管理员都能看到技术图表入口。
- 点击菜单能进入 `/technical-chart`，当前菜单有激活状态。
- 直接访问 `/technical-chart` 不出现 404 或白屏。
- 认证开启且未登录时，遵循现有登录重定向；登录后能回到原始地址。

### 查询参数

- `?stock=600519` 能直接加载对应股票。
- 非法 `period`、超出范围的 `days` 或空股票代码不会导致前端异常。
- 页面内切换股票后刷新浏览器仍能恢复当前上下文。

### 响应式与可用性

- PC / Mac 侧边栏、移动端抽屉导航均可进入页面。
- 移动端图表可横向查看，核心指标和 tooltip 不被截断。
- 图表失败时页面仍保留股票搜索和重试入口。
- 中英文切换后导航和页面关键文案均有对应翻译。

## 11. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 一级菜单过多导致导航拥挤 | 第一版保持一级入口，后续按“市场分析”分组；不在本次增加更多入口 |
| 图表库加载影响首页性能 | 路由和图表组件懒加载，避免在 `App` 静态导入图表库 |
| 页面与历史抽屉出现两套图表逻辑 | 统一复用 `TechnicalChart` 数据和展示组件，抽屉只保留轻量摘要 |
| 用户从旧链接进入时没有股票参数 | 提供搜索、最近股票和自选股空状态，不阻塞页面使用 |
| 认证模式差异导致入口行为不一致 | 不新增页面级认证分支，统一使用现有 `AuthContext` 和路由守卫 |

回滚时优先移除侧边栏入口和路由注册，保留原有首页历史趋势功能；若技术图表 API 已上线，则独立停用新页面调用，不修改现有历史行情接口。

## 12. 开发前置决策

进入 Cursor 实现前，需要确认：

1. 页面名称最终使用“技术图表”还是“行情图表”。本规划推荐“技术图表”。
2. 路由是否确定为 `/technical-chart`。
3. 是否第一阶段就增加首页、选股、持仓的快捷跳转，还是先只上线侧边栏入口。
4. 页面无股票时使用股票搜索、最近股票还是自选股作为主入口。
5. 技术图表 API 完成后，是否同步改造历史趋势抽屉。
