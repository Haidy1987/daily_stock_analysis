# 技术图表后端能力评估与补全计划

## 1. 结论

当前后端不能直接满足技术图表独立页面的完整调用需求，只能满足基础日线 K 线的部分需求。

当前已具备：

- `GET /api/v1/stocks/{stock_code}/history` 基础历史行情接口。
- OHLCV、成交额和涨跌幅字段。
- `src/stock_analyzer.py` 中已有 MA5/10/20、MACD 12/26/9、RSI6/12/24、BIAS、量比和部分支撑压力计算。
- 数据源管理器具备日线数据获取和多数据源 fallback 能力。

当前不具备：

- 面向图表的技术指标时间序列 API。
- 每个 K 线日期对应的 MA、MACD、RSI、量比等完整序列。
- KDJ、CCI、BOLL 的计算和返回字段。
- 可供图表使用的统一支撑压力摘要契约。
- 实际可用的周线/月线服务层实现。
- 能区分“无数据”和“数据源失败”的历史行情错误语义。

因此，页面结构可以先设计和实现空状态，但在后端补全前不能完成真实图表联调。本项目完成的定义是 P0、P1、P2 全部完成，BOLL、KDJ、CCI、BIAS 不是可选增强项。

## 2. 当前实现核对

### 2.1 现有历史接口

当前接口：

```text
GET /api/v1/stocks/{stock_code}/history
```

响应模型 `KLineData` 目前提供：

- `date`
- `open`
- `high`
- `low`
- `close`
- `volume`
- `amount`
- `change_percent`

该接口可以支撑最初的 K 线和成交量图，但不能直接支撑均线、MACD、RSI 和支撑压力的曲线展示。

### 2.2 周期能力存在契约漂移

接口层的 `period` 参数声明了 `daily`、`weekly`、`monthly`，但 `src/services/stock_service.py` 当前对非 `daily` 周期抛出“不支持”的错误。页面不能依据接口声明直接开放周线/月线按钮，否则用户会看到可点击但必然失败的功能。

补全前的页面策略：

- 第一版后端 MVP 只开放日线。
- 周线/月线可以暂时隐藏，或明确显示“即将支持”并禁用。
- 只有完成聚合逻辑和测试后，才在页面启用对应周期。

### 2.3 数据点范围不足

当前历史接口默认 `days=30`，上限为 365；页面规划建议默认 120，并预留 250～500 个数据点。MACD、RSI 和后续 BOLL 等指标还需要计算预热窗口，不能只请求最终展示数量。

补全时需要明确：

- `display_days`：用户实际看到的数据点数量。
- `calculation_days`：后端为了计算指标额外拉取的历史数据量。
- 返回结果只保留展示窗口，指标计算使用完整预热窗口。

## 3. 现有指标能力与图表需求的映射

| 指标 | 当前后端情况 | 是否可直接给页面使用 | 补全要求 |
| --- | --- | --- | --- |
| MA5/10/20 | `_calculate_mas` 已计算 | 否，仅用于内部分析结果 | 输出每个日期的 MA 序列，并将空值保留为 `null` |
| MACD | `_calculate_macd` 已计算，柱值为 `(DIF - DEA) * 2` | 否，仅提取最新值 | 输出每个日期的 DIF、DEA、柱值，固定版本和参数 |
| RSI6/12/24 | `_calculate_rsi` 已计算，使用 Wilder EMA / SMMA 口径 | 否，仅提取最新值 | 输出每个日期的 RSI 序列，明确初始值和空值规则 |
| 量比 | `_analyze_volume` 计算最新 5 日量比 | 否，仅有最新值 | 计算每个日期的量比，并定义首个可计算日期 |
| 放量/缩量 | 有最新状态枚举 | 否，仅有最新状态 | 生成每根 K 线的状态，或明确只在 summary 返回最新状态 |
| 支撑压力 | 有最新报告级列表，主要来自 MA 和近期高点 | 否，算法契约不适合直接画历史线 | 抽取无未来数据算法，返回 summary levels 和日期/来源 |
| BIAS | 已有最新 MA 乖离率 | 否，仅有最新值 | 输出 BIAS5/10/20 序列，并固定 MA 口径 |
| BOLL | 未发现现有统一实现 | 否 | 新增上中下轨、带宽、价格位置计算和测试 |
| KDJ | 未发现现有统一实现 | 否 | 新增 K/D/J 计算、平滑和边界测试 |
| CCI | 未发现现有统一实现 | 否 | 新增 CCI、参考线和除零处理测试 |

关键原则：不要把 `TrendAnalysisResult` 中的最新指标字段直接扩展成“假序列”，应建立面向时间序列的统一计算结果。

## 4. 建议新增后端契约

### 4.1 新增独立接口

```text
GET /api/v1/stocks/{stock_code}/technical-chart
```

建议第一阶段参数：

| 参数 | 第一阶段建议 |
| --- | --- |
| `period` | 先只允许 `daily`；周线/月线待聚合逻辑完成后放开 |
| `days` | 60～250；服务端保留未来扩展到 500 的能力 |
| `indicators` | 支持 `ma,volume,macd,rsi,boll,kdj,cci,bias,support_resistance`；默认请求完整指标集 |

### 4.2 响应建议

建议沿用技术图表需求文档中的 `items` + `summary` 结构，核心字段如下：

```json
{
  "stock_code": "600519",
  "stock_name": "贵州茅台",
  "period": "daily",
  "range_days": 120,
  "calculation_version": "technical-v1",
  "data_status": "available",
  "items": [
    {
      "date": "2026-07-13",
      "open": 1000.0,
      "high": 1015.0,
      "low": 995.0,
      "close": 1010.0,
      "volume": 123456,
      "amount": null,
      "change_percent": 1.2,
      "ma5": 1002.0,
      "ma10": 998.0,
      "ma20": 990.0,
      "volume_ratio": 1.35,
      "volume_status": "normal",
      "macd_dif": 8.1,
      "macd_dea": 6.7,
      "macd_bar": 2.8,
      "rsi6": 62.0,
      "rsi12": 57.0,
      "rsi24": 54.0
    }
  ],
  "summary": {
    "latest_close": 1010.0,
    "latest_change_percent": 1.2,
    "support_levels": [],
    "resistance_levels": [],
    "recent_high": null,
    "recent_low": null
  }
}
```

### 4.3 字段语义

- `items` 按日期升序返回。
- 指标计算周期不足时返回 `null`，不得填 0。
- `data_status` 至少区分 `available`、`empty`、`source_unavailable`、`partial`。
- 数据源 fallback 信息只返回低敏状态和来源标签，不暴露密钥或内部异常堆栈。
- `calculation_version` 发生变化时，应能使缓存失效并支持结果追溯。
- `summary.support_levels` 和 `summary.resistance_levels` 每项建议包含 `price`、`label`、`date`、`source`，便于前端标注。

## 5. 后端补全任务

### P0：日线图表可用

1. 新增技术图表 Schema。
2. 新增技术图表 API，不修改旧 history 响应结构。
3. 抽取共享的 MA、MACD、RSI、量比计算函数。
4. 为每个日期输出 OHLCV、MA、MACD、RSI 和量比字段。
5. 固定 MACD `(DIF - DEA) * 2`、RSI Wilder EMA / SMMA 等现有口径。
6. 统一空值、缺失值和数据不足处理。
7. 明确支撑压力算法，禁止使用未来 K 线参与当前日期判断。
8. 补充正常、数据不足、无数据、非法参数和数据源异常测试。

### P1：周期和稳定性

1. 在服务层实现周线/月线聚合，而不是仅在 API 层放开枚举。
2. 固定周线/月线的开高低收、成交量和日期边界口径。
3. 增加技术图表缓存，缓存键至少包含股票、周期、展示范围、指标集合和计算版本。
4. 将数据源异常和空数据分成不同响应状态。
5. 增加接口性能和多数据源 fallback 验证。

### P2：完整指标集（本期必达，不是可选增强）

1. 增加 BOLL 上中下轨、带宽和价格位置。
2. 增加 KDJ、CCI、BIAS 序列。
3. 增加完整指标的 API Schema、前端字段映射和 tooltip 展示。
4. 增加完整指标的固定样本回归测试、数据不足测试和除零测试。
5. 增加参数版本化和可选指标校验。
6. 评估将指标结果写入本地缓存或复用已有行情缓存。

## 6. 与页面的调用顺序

页面加载时建议采用以下顺序：

1. 前端读取和校验 URL 中的股票、周期、范围和指标参数。
2. 无股票时只显示空状态，不调用技术图表接口。
3. 有股票时调用技术图表接口。
4. API 返回 `available` 后渲染图表。
5. API 返回 `partial` 时渲染可用数据，并对缺失指标显示提示。
6. API 返回 `empty` 或 `source_unavailable` 时展示对应状态和重试入口。

不建议页面先调用旧 history 接口，再在前端计算指标作为长期方案；这样会造成算法分散、结果难以校验，也无法统一处理支撑压力和计算版本。

## 7. 验收标准

### API

- 技术图表接口能返回至少 60～250 个日线数据点。
- 每个返回数据点包含 OHLCV 和第一版指标字段。
- MA、MACD、RSI、BOLL、KDJ、CCI、BIAS 结果与固定样本和约定公式一致。
- 首个有效指标点的位置符合计算周期和预热规则。
- 旧 history 接口仍保持兼容。
- 周线/月线未完成前，接口明确拒绝或不声明支持，而不是返回错误的日线数据。

### 页面联调

- 页面可以直接使用新接口完成首次渲染。
- tooltip 能从同一数据点读取主图和副图指标。
- 所有本期指标均能通过接口返回并在页面打开、关闭和查看明细。
- 后端返回空值时前端不画出虚假 0 线。
- 数据源失败和无数据在页面上显示不同提示。
- 接口性能满足第一版页面交互要求。

## 8. 回滚方案

- 新增技术图表 API 独立回滚，不修改现有 history API。
- 页面入口可以通过路由和菜单配置移除，恢复原有首页历史趋势入口。
- 共享指标计算抽取失败时，保留 `StockTrendAnalyzer` 原有调用路径，不影响报告分析。
- 缓存异常时可临时关闭技术图表缓存，改为实时计算或沿用行情缓存。
