# 技术指标图表第一版需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 需求评审 |
| 版本 | v1.0 |
| 适用端 | Web 端、桌面端内嵌 Web 页面、移动端浏览器 |
| 目标页面 | 股票历史行情 / 股票详情中的历史趋势区域 |
| 关联模块 | `api/v1/stocks`、`src/stock_analyzer.py`、`apps/dsa-web/src/components/history/StockHistoryTrendDrawer.tsx` |

## 2. 背景与问题

当前项目已经能够提供股票历史 OHLCV 数据，并在后端报告分析中计算部分技术指标，但前端尚未形成一个统一的技术指标图表体验。用户需要在同一张图表中观察价格趋势、均线、成交量、动量指标和支撑压力，减少在文字报告与行情数据之间来回切换。

当前需求采用分阶段交付，但本期完成定义包含全部指标。先建立稳定的图表数据契约、图表容器和交互基础，再按阶段完成 BOLL、KDJ、CCI、BIAS 的后端计算、API 返回和前端展示。

## 3. 需求目标

1. 在股票历史行情页面提供可缩放、可悬停查看详情的 K 线技术分析图。
2. 本期完整实现 K 线、MA、成交量、MACD、RSI、BOLL、KDJ、CCI、BIAS 和支撑压力。
3. 技术指标统一由后端计算，前端只负责展示，避免前后端算法不一致。
4. 保留现有历史行情 API 的兼容性，不破坏已有页面和调用方。
5. 图表在 PC、Mac、移动端浏览器和桌面端内嵌 Web 页面中具备基本可用性。
6. 为后续增加自定义指标周期、参数模板和策略信号预留扩展字段和指标选择机制。

## 4. 第一版范围

| 指标类别 | 第一版要求 | 展示位置 |
| --- | --- | --- |

| 均线 MA | MA5、MA10、MA20 | 主图叠加线 |
| 成交量 | 成交量柱、上涨/下跌颜色、成交量变化；可显示量比和放量/缩量状态 | 成交量副图 |
| MACD | DIF、DEA、MACD 柱；参数 12/26/9 | 副图 |
| RSI | RSI6、RSI12、RSI24；30/70 超买超卖参考线 | 副图 |
| 支撑压力 | 支撑位、压力位、近期高点、近期低点 | 主图标线/标注 |

### 4.2 必须实现的完整指标集

以下指标全部属于本期必做范围，阶段划分只代表开发顺序，不代表可以延期到下一版本：

| 指标类别 | 必须实现的字段 | 展示位置 |
| --- | --- | --- |
| BOLL | 上轨、中轨、下轨、带宽、价格位置 | 主图叠加线；带宽和价格位置放入 tooltip 或指标图例 |
| KDJ | K、D、J | 副图 |

### 4.3 不在范围内

- 自动交易、下单、持仓管理或投资建议。
- 基于指标的回测、策略收益排名和模拟盘。
- 前端自行计算指标并覆盖后端结果。
- 第一版保存用户个性化指标模板、跨设备同步和分享图表。
- 第一版导出图片、导出 CSV 或生成 PDF 报告。

## 5. 用户场景

### 场景一：查看股票趋势

用户打开股票历史行情，默认看到最近一段时间的 K 线和 MA5、MA10、MA20，能够判断价格与均线的相对位置。

### 场景二：观察量价配合

用户通过成交量副图观察放量、缩量以及价格上涨/下跌与成交量之间的配合关系。

### 场景三：观察短中期动量

用户查看 MACD 和 RSI，了解趋势动量与超买超卖参考状态。页面只展示指标事实和参考线，不输出确定性买卖结论。

### 场景四：定位关键价格区域

用户在主图中看到支撑位、压力位、近期高点和近期低点，辅助理解当前价格所处区间。

### 场景五：移动端查看

用户在手机上查看同一股票时，可以通过横向滑动、缩放和指标开关查看完整数据，核心数值不会因屏幕较窄而不可读。

## 6. 页面与交互需求

### 6.1 图表区域布局

建议将图表集成到现有历史趋势抽屉或股票详情历史行情区域，第一版采用上下联动的多面板布局：

1. 主图：K 线、MA5/MA10/MA20、BOLL、支撑压力和近期高低点。
2. 成交量副图：成交量柱，必要时在 tooltip 中显示量比和量价状态。
3. MACD 副图：DIF、DEA 和柱状图。
4. RSI 副图：RSI6、RSI12、RSI24 及 30/70 参考线。

不要默认同时展示所有可选指标，以免在移动端造成信息过载。后续指标应通过“指标开关”或“副图指标选择器”加入。

### 6.2 顶部控制区

第一版至少提供：

- 周期切换：第一版先开放日线；周线、月线需等后端完成聚合和测试后再启用，不以 API 枚举声明代替实际能力。
- 时间范围：最近 60、120、250 个数据点；默认 120 或按页面空间选择合理默认值。
- 指标开关：MA、BOLL、成交量、MACD、RSI、KDJ、CCI、BIAS。
- 重置视图：恢复默认缩放和默认指标。

### 6.3 图表交互

- 鼠标或手指移动时显示十字光标，并同步显示各面板同一日期的数据。
- tooltip 显示日期、OHLC、涨跌幅、成交量、均线、MACD、RSI 和量比等当前可用字段。
- 支持拖动和缩放；移动端优先保证横向查看最近数据的体验。
- 主图与副图使用同一时间轴，不能出现日期错位。
- 数据加载时显示 loading；无数据、数据不足、接口失败时显示明确状态和重试入口。
- 指标值不足其计算周期时显示为空，不使用 0 伪造数据。
- 红涨绿跌沿用项目现有行情颜色约定，并兼容深色/浅色主题。

### 6.4 支撑压力展示

- 支撑位和压力位使用主图水平标线或标注区域展示。
- 近期高点、近期低点应显示对应价格和日期。
- 标线不能遮挡 K 线关键信息；多个水平位接近时应避免文字重叠。
- 支撑压力只作为历史技术参考，不显示“必然突破”“确定买入”等确定性结论。

## 7. 后端数据与 API 需求

### 7.1 API 设计原则

建议新增独立技术图表接口，不直接改变现有历史行情接口的返回结构：

```text
GET /api/v1/stocks/{stock_code}/technical-chart
```

建议查询参数：

| 参数 | 必填 | 取值 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `period` | 否 | 第一阶段 `daily`；后续 `weekly` / `monthly` | `daily` | K 线周期；周线/月线需后端实际支持后开放 |
| `days` | 否 | 60～500 | 120 | 返回数据点数量上限 |
| `indicators` | 否 | 逗号分隔的指标名 | `ma,volume,macd,rsi,support_resistance` | 控制计算和返回内容 |

现有 `GET /api/v1/stocks/{stock_code}/history` 继续保持兼容，原有调用方无需迁移。

### 7.2 建议响应结构

```json
{
  "stock_code": "600519",
  "stock_name": "贵州茅台",
  "period": "daily",
  "range_days": 120,
  "calculation_version": "technical-v1",
  "items": [
    {
      "date": "2026-07-13",
      "open": 1000.0,
      "high": 1015.0,
      "low": 995.0,
      "close": 1010.0,
      "volume": 123456,
      "amount": null,
      "change_percent": 1.2,
      "ma5": 1002.0,
      "ma10": 998.0,
      "ma20": 990.0,
      "volume_ratio": 1.35,
      "volume_status": "normal",
      "macd_dif": 8.1,
      "macd_dea": 6.7,
      "macd_bar": 2.8,
      "rsi6": 62.0,
      "rsi12": 57.0,
      "rsi24": 54.0
    }
  ],
  "summary": {
    "latest_close": 1010.0,
    "support_levels": [],
    "resistance_levels": [],
    "recent_high": null,
    "recent_low": null
  }
}
```

字段要求：

- 所有指标字段均允许为 `null`，用于表示计算周期不足或数据缺失。
- `items` 按日期升序返回，前端不再自行重新排序或计算指标。
- `calculation_version` 用于后续算法调整、缓存失效和结果追溯。
- `summary` 为主图标线提供统一数据来源，避免前端从历史数组中重复推断支撑压力。
- 如果某项指标未在 `indicators` 中请求，可以省略对应字段或返回 `null`，但需要在 API 文档中固定一种约定。

### 7.3 计算口径

| 指标 | 第一版口径 |
| --- | --- |
| MA | 简单移动平均，周期 5、10、20 |
| MACD | DIF 使用 EMA12 - EMA26，DEA 为 DIF 的 EMA9；柱值沿用当前项目约定，需在测试中固定是否为 `(DIF - DEA) * 2` |
| RSI | RSI6、RSI12、RSI24，沿用当前后端已有实现和边界处理 |
| 量比 | 优先沿用当前后端已有的 5 日均量比较口径，并明确分母为 0 或数据不足时的处理 |
| 放量/缩量 | 沿用当前项目阈值；默认建议低于 0.7 为缩量、高于 1.5 为放量，其余为正常 |
| 支撑压力 | 使用历史窗口内的明确算法；不得使用未来 K 线参与当前时点判断，避免 look-ahead bias |
| BOLL | 默认周期 20、标准差倍数 2；输出上轨、中轨、下轨、带宽和价格在通道中的位置 |
| KDJ | 默认 RSV 周期 9、K/D 平滑参数 3/3；固定初始化和除零处理 |
| CCI | 默认周期 14；基于典型价格、移动平均和平均偏差计算，固定除零处理 |
| BIAS | 基于 MA5、MA10、MA20 计算 `(close - MA) / MA * 100` |

如果现有报告计算结果与图表需求存在差异，应先抽取为共享计算模块或明确版本化适配层，不应在前端复制一套近似算法。

### 7.4 缓存与性能

- 技术指标结果应尽量复用已有行情数据缓存。
- 同一股票、周期、时间范围和指标集合的重复请求应具备缓存能力。
- 第一版建议限制单次返回最多 500 个数据点，避免移动端一次渲染过多数据。
- 目标：缓存命中时接口 P95 小于 1.5 秒；未命中时不阻塞其他页面功能，并返回可理解的失败信息。
- 数据源暂时不可用时，应区分“无历史数据”和“数据源暂时失败”，便于用户判断是否重试。

## 8. 前端实现要求

### 8.1 组件边界

建议将图表拆分为以下职责：

- `TechnicalChartContainer`：请求数据、管理周期和时间范围。
- `TechnicalChartToolbar`：管理指标开关和视图控制。
- `TechnicalChart`：负责多面板图表渲染和联动。
- `TechnicalChartLegend`：展示当前日期的指标值和颜色说明。
- `TechnicalChartEmptyState`：处理加载失败、无数据和数据不足。

具体命名可根据现有前端目录和组件规范调整，不要求为了命名强行新增过多文件。

### 8.2 图表库建议

技术选型优先评估 Apache ECharts，原因是其对 K 线、柱状图、多坐标轴、dataZoom、markLine、markArea 和多面板联动支持较完整。若项目更强调包体积瘦身，可评估 Lightweight Charts，但必须确认支撑压力标注、MACD/RSI 多面板和移动端交互是否满足需求。

第一版只引入一种主图表方案，不同时引入多个重型图表库。实现前需要比较现有 Recharts 能力、打包体积和维护成本，并记录最终选择。

### 8.3 兼容性

- 不影响现有历史趋势图和报告页面的正常访问。
- API 请求失败不能导致股票详情页整体崩溃。
- 组件在窄屏下允许折叠或切换副图，不强制所有面板同时展示。
- 主题颜色、字体和间距应复用现有 Web 设计系统。
- 桌面端只要复用 Web 页面入口即可，不新增独立的桌面图表实现。

## 9. 多用户与权限要求

- 市场行情和技术指标属于公共数据，第一版不需要按用户复制存储。
- 图表查询接口不应依赖 `user_id`，登录策略沿用现有项目配置。
- 后续如果增加“保存指标组合”“保存时间范围”等偏好，必须单独设计用户归属字段，并通过当前认证用户隔离。
- 管理员用户管理、普通用户数据隔离和图表展示数据不混为同一权限模型。

## 10. 验收标准

### 10.1 数据验收

- 给定股票和周期，API 能返回按日期升序排列的 OHLCV 数据。
- MA5、MA10、MA20、MACD、RSI、BOLL、KDJ、CCI、BIAS 的结果与固定计算口径一致。
- 数据不足时对应字段为 `null`，不会显示为 0 或产生虚假曲线。
- 支撑压力数据能够在主图中正确定位，且算法不使用未来数据。
- 现有历史行情 API 的响应结构和原页面行为不变。

### 10.2 页面验收

- 默认打开页面可以看到 K 线、MA、BOLL、成交量、MACD、RSI；KDJ、CCI、BIAS 可通过指标选择器打开。
- 所有本期指标均可独立打开、关闭和在 tooltip 中查看，不因副图空间限制而缺少实现。
- 周期、时间范围和指标开关能够生效，切换后没有日期错位。
- tooltip / 十字光标能同步展示各面板同一日期的值。
- 支撑位、压力位、近期高低点可读且不会严重遮挡 K 线。
- 无数据、加载中、接口失败和数据不足均有明确界面状态。
- PC、Mac 浏览器和手机窄屏下均可完成基本查看操作。
- 深色和浅色主题下文字、线条、柱状图具有足够对比度。

### 10.3 验证要求

- 后端补充指标计算和 API 测试，至少覆盖正常数据、数据不足、缺失值和非法参数。
- 前端执行 lint 和 build，并完成至少一个真实股票的接口联调。
- 页面变更需提供截图或其他可视化验收证据；临时验收截图不提交到仓库。
- 若新增依赖，需要记录包体积和许可证影响。

## 11. 分阶段实施建议

### 阶段一：数据契约与后端

1. 梳理当前 `src/stock_analyzer.py` 中已有指标实现和历史数据结构。
2. 抽取或复用统一指标计算函数，固定参数、空值和舍入规则。
3. 新增技术图表响应 Schema 和独立 API。
4. 补充接口、计算口径和边界条件测试。

### 阶段二：第一版前端图表

1. 在现有历史趋势区域接入技术图表接口。
2. 实现主图 K 线 + MA + 支撑压力。
3. 实现成交量、MACD、RSI 副图和时间轴联动。
4. 实现周期、时间范围、指标开关、loading 和错误状态。
5. 完成 PC、Mac 和移动端响应式验证。

### 阶段三：完整指标交付（本期必达）

1. 增加 BOLL、KDJ、CCI、BIAS。
2. 完成所有指标的前端展示、tooltip、空值和移动端切换。
3. 完成全量指标的固定样本回归测试。

### 阶段四：后续增强（不影响本期完整指标交付）

1. 增加指标参数配置和用户级保存。
2. 增加图表导出、报告引用和策略信号展示（另行评审）。

## 12. 风险、取舍与回滚

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 后端报告与图表计算口径不一致 | 用户看到的数值不一致 | 复用共享计算逻辑，并用固定样本做回归测试 |
| 一次展示指标过多 | 移动端难以阅读、性能下降 | 默认只开核心指标，副图使用开关或选择器 |
| 引入图表库导致包体积增大 | Web / 桌面端加载变慢 | 在实现前比较 ECharts、Lightweight Charts 和现有 Recharts 的成本 |
| 支撑压力算法存在未来数据 | 形成误导性历史信号 | 采用无未来数据算法，并在测试中验证时间窗口边界 |
| 行情数据源不稳定 | 图表无法加载 | 区分缓存、无数据和数据源失败，提供重试和降级状态 |
| API 改动影响旧客户端 | 现有页面回归 | 新增独立接口，保留旧 history 接口 |

回滚方式：第一版前端通过功能开关或路由入口关闭技术图表，恢复使用现有历史趋势组件；后端保留独立技术图表接口，不修改旧接口契约，必要时可单独下线新接口。

## 13. 待评审决策

在进入 Cursor 分阶段实现前，需要确认以下事项：

1. 第一版是否采用 Apache ECharts，还是优先采用更轻量的 Lightweight Charts。
2. 支撑压力的具体算法和展示窗口。
3. MACD 柱值是否严格沿用当前项目的 `(DIF - DEA) * 2` 约定。
4. 时间范围默认使用 120 个还是 250 个数据点。
5. 第一版是否允许将量比和放量/缩量状态直接放入 tooltip，还是在成交量副图中增加文字标注。
6. 是否需要在完整指标交付后，再单独拆分自定义参数、用户模板和策略信号需求。
