# Cursor 提词 04：多用户测试、部署与切换

## 前置条件

阶段 0 至阶段 3 已完成，并且所有阶段的阻断问题已经关闭。不要在生产数据库上直接试验未验证的迁移。

## 提词正文

```text
你正在维护 daily_stock_analysis 项目。先读取 AGENTS.md、总体多用户规划和阶段 0-3 的交付记录。

本阶段目标：完成多用户系统的集成验收、数据库备份恢复、Docker/Traefik 部署准备和从 single_admin 到 multi_user 的可回滚切换。

验证矩阵：

1. 认证：登录、退出、过期、改密、logout-all、禁用用户、限流和错误码。
2. 权限：admin/user 角色边界、管理员 API、系统配置和敏感信息脱敏。
3. 隔离：用户 A/B 对历史、报告、自选股、持仓、提醒、会话、信号和使用量的读/改/删交叉测试。
4. 异步链路：后台分析任务、任务轮询、SSE/stream、报告保存、通知发送和失败重试中的 user_id。
5. 数据库：迁移幂等性、旧数据归属、索引、WAL、锁竞争、备份和恢复。
6. Web：登录、登出、管理员用户管理、个人中心、桌面宽屏和手机窄屏布局。
7. 部署：Docker build、Compose config、容器健康检查、Traefik HTTPS、Secure Cookie 和重启持久化。

必须新增或补齐：

- 认证单元测试和 API 集成测试。
- 跨用户越权回归测试，测试必须走真实认证上下文和真实 Repository。
- 数据库迁移测试：空库、已有单管理员库、已有历史数据的库。
- 备份校验和恢复演练脚本/说明。
- 多用户部署说明、配置说明和回滚说明。

上线前操作：

1. 在独立数据库副本执行迁移并记录版本。
2. 检查用户私有表的数据计数和 user_id 空值。
3. 备份服务器 data/、.env、Compose 文件和当前镜像标签；备份中不得把密钥提交到仓库或日志。
4. 先以 single_admin 启动并确认旧管理员可以登录。
5. 创建测试用户 A/B，完成隔离验收。
6. 再切换 AUTH_MODE=multi_user，滚动重启 server。
7. 观察登录失败、数据库锁、后台任务、通知和容器日志。
8. 验收通过后再允许管理员创建真实用户。

回滚规则：

- 优先回滚应用镜像，不先删除迁移后的表或字段。
- 可逆配置问题将 AUTH_MODE 恢复为 single_admin。
- 数据损坏或不可逆迁移才停止服务并从停机前备份恢复 data/。
- 禁止使用旧版本程序写入已经完成破坏性迁移的数据库。
- 记录回滚时间、数据库备份版本、镜像版本和影响范围。

命令要求：

- 先执行与改动面匹配的离线验证，再做网络或远程部署验证。
- Docker/Traefik 验证必须说明实际运行的 Compose 文件、域名和容器健康状态。
- 不执行 git commit、push、tag，不修改无关服务，不删除现有生产数据。

交付时输出一份验收报告：测试矩阵、命令和结果、数据库迁移结果、部署结果、未验证项、风险、监控观察项和回滚步骤。
```

## 阶段验收

- 测试覆盖认证、权限、隔离、异步链路和迁移。
- 备份可以恢复，迁移可以在副本重复执行。
- Docker 服务健康，HTTPS 和 Cookie 行为正确。
- single_admin 与 multi_user 都有明确切换和回滚路径。
- 没有把真实密钥、数据库备份或临时验收截图提交到仓库。
